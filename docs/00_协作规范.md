## 1. 硬红线

> 这一节请**原样粘贴**到每个组员给 agent 的提示词开头。

### 1.1 数据库

- **只能连接 `gaokao3`。** 禁止连接 `gaokao`（已冻结的历史库）和 `gaokao2`（缺 `poi_transport` 等表）。
- **全程只读。** 禁止 `INSERT / UPDATE / DELETE / ALTER / DROP / CREATE`，包括建视图、建索引、建临时表以外的任何结构变更。
- 禁止把 `stg_*`、`stg_exception_ledger`、`campus_candidate`、`query_session*`、`candidate_profile` 及任何 QA/exception 表暴露给前端。
- 数据库账号密码只写在 `.env`，**永不提交**。仓库只放 `.env.example`。
- 不得为了"接口好写"而补索引、建视图、清洗数据。发现 P3 问题**登记不改**。

### 1.2 坐标与空间语义

- 库内与接口统一 **WGS84 / EPSG:4326**。
- GeoJSON 坐标顺序**固定 `[longitude, latitude]`**。前端不得自行交换或"纠正"经纬度。
- 底图**优先选与 WGS84 兼容的**。若使用国内偏移底图（GCJ02/BD09），必须走独立显示适配层，**严禁把 WGS84 坐标不换算就当 GCJ02 用**。
- 业务距离一律**米制测地距离**（`geom::geography`），API 对外可返回 km。
- `ST_DWithin` / `ST_Distance` 直接对 `geometry` 传米数是错的——那是在比"度"。

### 1.3 业务不变量（Gate 项，违反即失败）

- **无空间条件时，没有 Campus 的 College 必须照常出现在结果里。** 只有启用距离/Polygon 后才允许被空间条件排除，并且必须通过 `warnings` 说明空间覆盖不足。
- **`CONFIRMED` 与 `CANDIDATE` 不得混淆。** 地图可同时显示，但必须不同符号 + 图例 + 详情标注。`CANDIDATE` 统一文案：**"候选校区点，尚未完成实体级人工核验"**。
- 附近/距离查询**默认只用 `CONFIRMED`**，用户主动开启"包含候选校区"后才纳入 `CANDIDATE`。
- 缺失值返回 `null`，**不推算、不补 0、不伪造**。
- `category` / `batch` 是**来源原始口径**，前端与 API 均不得宣称已完成全国标准化。

### 1.4 提交纪律

- **禁止把数据文件提交进仓库。** 尤其禁止 `gaokao*.sql` 数据库备份（本机存在 1.27 GB 的 `gaokao2_full_20260915.sql`）。一次 `git add .` 就会写进 history，之后要重写历史才能删掉。
- 禁止 `.env`、密钥、`.pem`。
- 禁止 `node_modules/`、`.venv/`、`dist/`。
- 原始 shapefile / 大 GeoJSON 走网盘共享，仓库只放 SQL 脚本与代码。
- Mock 用的小样例 GeoJSON（几 KB）可以进仓库，放在 `frontend/src/mocks/`。

## 2. 分支模型

| 分支 | 用途 | 保护 |
|---|---|---|
| `main` | 稳定可演示版本，随时能跑 | 禁止直接 push、禁止 force push、**合并需 1 人 review** |
| `dev` | 集成所有人的功能 | 禁止 force push、**不强制 review**（谁的功能谁合，快跑） |
| `feature/*` | 个人功能分支，从 `dev` 拉 | 无 |

**双轨的理由**：四人各跑 agent，PR 量按小时计。`dev` 是快车道，追求集成速度；`main` 是发布道，到里程碑才慢下来。要求每个 PR 都过人审会把唯一能审的人变成瓶颈。

分支命名（**统一，用这个**）：

```
feature/be-core          莫炜钧  FastAPI 骨架 + College/地图/空间 API
feature/be-admission     倪嵩    /meta/filters + /admissions + search 招生子查询
feature/fe-map           高天恒  Leaflet / Campus / AdminRegion / 绘制
feature/fe-ui            范传智  Vue 布局 / 筛选 / 列表 / Drawer / 对比 / 导出
fix/xxx                  任何人
```

流程：

```
git pull origin dev
git checkout -b feature/xxx
# 写代码，频繁小提交
git push origin feature/xxx
# 网页提 PR → 目标分支 dev → 合并 → 删掉 feature 分支
```

提交信息：`feat: 实现 /api/spatial/nearby` / `fix: 修正 KNN 平面距离排序` / `docs: 补充契约字段说明`。
**不要**写"更新"、"改了"、"一堆文件"。

## 4. 契约冻结与 Mock

- `docs/api-contract.md` 是仓库内**唯一真源**。执行书是 .docx，agent 读不了，所以必须有这个 markdown 副本。
- 后端按契约实现；前端按契约写 Mock。**两边字段名必须逐字一致。**
- 前端联调时**只换数据源，不改组件字段**。如果发现换真接口后要改字段，说明契约被某一方违反了，停下来对齐，不要各改各的。
- 统一约定（不许自行发挥）：
  - 前缀 `/api`，V1 不引 `/api/v1`
  - 字段全 `snake_case`，API ↔ 前端**不做二次映射**
  - 分页列表：`{"items": [], "total": 0, "page": 1, "page_size": 20, "warnings": []}`
  - 单对象：`{"data": {}}`
  - 错误：沿用 FastAPI `{"detail": "..."}`
  - `warnings` 是给用户看的人话，**不得暴露内部 QA 表结构**

## 5. 数据现状：接口层必须处理的三个坑

这三条不是"注意一下"，是**会直接导致接口返回错数据**的：

**① `college.reg_province` 装的是「市」，不是「省」。**
346 个不同值，实际是 `长春市` / `盐城市` / `苏州市`。契约里 API 1 的参数名是 `reg_province`，会误导前端。
→ 按省筛**不要用这个字段**。走 `admin_region`（有 `parent_adcode`，省→市→区三级），或在 service 层建市名→省 adcode 映射。**这条需要全组确认后写进契约。**

**② `college.nature` 全空（2,952/2,952）、`status` 空 2,096 行。**
两个字段都不能作为 V1 筛选条件。`edu_level` 可以（只有 `本科` 1,412 / `高职（专科）` 1,540）。

**③ `school_admission` 里 `admit_count = 0` 是真实源数据值，不是缺失。**
例：北京理工大学在浙江的两行 `普通类一段`，`min_score` 652/656、`min_rank` 2184/8499、`admit_count` 都是 0。这种 0 很可能是"未公布"。
→ §1.3 说"缺失返回 null、不补 0"，但这里 0 是**源值**。要不要显示成"未公布"需要冻结口径，**不许某一方单方面改**。

## 6. 里程碑与完成定义

严格按执行书 §7，每个 Milestone **开发 → 联调 → PASS 后**才进下一个。不要等四个人全做完才第一次合并。

| M | 闭环 | PASS |
|---|---|---|
| M1 | College → FastAPI → Vue | 真实显示 College；能搜索；能开详情 |
| M2 | SchoolAdmission → FastAPI → Vue | 按生源省/年份看真实投档；筛选项来自后端元数据 |
| M3 | Campus/AdminRegion → API → Leaflet | 地图显示；CONFIRMED/CANDIDATE 区分；地图↔列表联动 |
| M4 | PostGIS → nearby/within → Leaflet | 选点、距离筛选、Polygon 真实运行；能解释空间覆盖不足 |

每个 Milestone **保留一个能跑的版本**，出问题能回退到上一个 PASS 点。

M4 与总验收 Gate 通过后**停止扩功能**（执行书 §8.3 Stop Rule）。不要临时加专业语义、登录、推荐、写库。
